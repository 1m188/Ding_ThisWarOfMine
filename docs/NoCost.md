# 制作不消耗资源 (NoCost)

## 功能语义

游戏里做东西要扣材料：点下制作、建造或升级后，仓库里的木材、零件、材料按配方数量被扣掉，扣到零就整格消失。

「制作不消耗资源」就是让这一步不生效：材料照常参与判断、照常做出成品或盖出房子，但仓库里的数量一点不少。名字虽然叫「制作」，意图是**所有要花材料的操作都不扣**——制作、建造、家具升级一视同仁，可以随便花销。

它和几个容易混的功能不一样：

- **无限资源**听起来像同一个东西，但游戏并没有「资源无限」的状态，实际能做到的就是「消耗时不扣」，所以功能名以「不消耗」为准。
- **无限背包空间**改的是「能放多少格」，不改数量。
- **无限工具耐久**改的是每件工具自己的耐久值，不改堆叠数量。
- **瞬间制作**改的是计时进度，不改材料。

覆盖面要说清楚：扣材料这一步是**一套公共逻辑**，制作、建造、家具升级都调它，所以一处改动三种操作同时生效。交易、丢弃、拾取、产出分发走的是另外的入口，不受影响。

## 游戏实现

### 物品放在哪

物品都在「容器」对象里，仓库、背包、工作台内部格用的是同一个结构：

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| `+0x18` | int | 条目数量 |
| `+0x20` | 指针 | 条目数组 |
| `+0x70` | int | 容量（格数） |

每个条目 0x40 字节：

| 偏移 | 含义 |
| --- | --- |
| `+0x18` | 物品定义指针（类别号取定义 `+0x180`） |
| `+0x20` | 物品定义指针（按它匹配「要取的是哪种」） |
| `+0x28` | 堆叠数量 |
| `+0x30` | 每件对象的数组 |
| `+0x38` | 件数组对象（压缩数组时交给它处理） |

每件对象 0x20 字节，`+0x1c` 是这一件是否占用的标记。工具、药物这类带耐久的东西，件对象里存着各自的状态。

### 取东西只有一个总闸

RVA 0x3E0310：

```c
void take_from_container(longlong dest, longlong src, longlong *item_def, int count);
```

- `src` 来源容器，`dest` 去向容器，`count < 0` 表示全拿，`*item_def` 等于全局量 `DAT_140834980` 表示「任意物品」。
- 逐件搬运：复制一件到目标容器里同种的条目，压掉来源里那一件，再 `DEC DWORD PTR [entry+0x28]`（RVA 0x3E04F8 与 0x3E072B 两处）。
- 某条目数量减到 0 就从容器里删掉（条目数 −1、数组前移）。
- 开始时广播事件 7，每搬一件广播事件 6（载荷带物品类别号），结束后刷新两个容器。

它自己是中性的：往里放、往外拿、交易、丢弃都调它。所以不能在这一层做「不扣」，否则交易和丢弃也会变成白给。

### 扣材料的那一步

真正决定「这次操作要扣多少」的是 RVA 0x342A60，签名：

```c
void collect_ingredients(longlong component, longlong *ctx, longlong *ingredient_list, longlong dest);
```

- `ctx[2]`（`+0x10`）是配方记录索引，配方记录 0x310 字节一条，表在 `[0x140926430]`；`ctx[3]`（`+0x18`）是材料的来源容器（仓库）。
- `ingredient_list` 里有材料条数（`+0x18`）、数组（`+0x20`，每条 0x18 字节）、批量除数（`+0x40`）；每条材料的 `+0xC` 是单件所需数量。
- 每种材料算一次数量，然后调 0x3E0310 把这些材料从仓库搬进目标容器：

```
数量 = ceil(单件所需 × 产出数量 / 批量除数) - 微小量取整
```

真正的调用点在 **RVA 0x342BEC**，机器码 `E8 1F D7 09 00`，整个文件里只有这一处（用字节搜索确认过）。

这个函数有三个调用者，正好对应三类操作：

| 调用者 | 用途 |
| --- | --- |
| RVA 0x3435D0 | 开始制作（设状态 3、算时长、广播 `OnBeginCrafting`、事件 0xF5） |
| RVA 0x342E20 | 开始建造或升级：先扣材料，再找或新建 `KosovoConstructionComponent`，广播事件 0xB0，处理建造台与工匠 |
| RVA 0x3432B0 | 同一组件状态机里的另一条开始路径 |

所以 RVA 0x342BEC 这一处就是「制作、建造、升级」共用的扣材料点。

### 扣完的材料去哪了

搬进目标容器只是暂存，之后还会被清掉：

- RVA 0x346C10（完成路径）：若配方记录 `+0xB8` 不等于 2，把工作台容器 `+0x128` 整批倒进全局容器 `0x140924F90`（任意物品 + 全拿），随后产出成品、广播事件 0xF5。
- RVA 0x343EC0（取消或重置）：状态清零、进度置 -1，把工作台容器 `+0x68` 里的东西倒回调用方给的容器，按情况广播事件 0x2E、0x74。
- RVA 0x343FB0（虚拟的「停止/结算」）：先按已完成比例把容器 `+0x68` 里的材料退一部分（RVA 0x3DFD50），再把外部容器整个拉进 `+0x68`。
- RVA 0x347920（组件事件处理）：事件 0xB0 时把上一个容器清空到载荷给的容器，新容器挂到 `+0x128`，配方 `+0xB8` 为 5/6 时广播 0xB1、0xB4。

### 其它动容器的路径

0x3E0310 还有一批调用者，都是「容器之间搬东西」而不是「从仓库扣材料」，例如完成时倒空、取消时返还、实体之间转交（RVA 0x348DA0）、产出分发（RVA 0x34A2E0 按随机目标分发）、放入物品时的借位（RVA 0x3E0C20）。这些不改也没关系，正好说明补丁点选在 0x342BEC 不会牵连交易和丢弃。

## 可选的功能实现方法

### 方案一：让扣材料这一步不发生（推荐）

把 RVA 0x342BEC 的 5 字节 `E8 1F D7 09 00` 改成 `90 90 90 90 90`。

材料不会离开仓库，操作照常开始、照常产出。三个入口（制作、建造、升级）共用这一个调用点，改一处三处生效；交易、丢弃、拾取不受影响。

代价：没有别的副作用。制作、建造、升级会同时变成不扣料，这正是本功能要的行为。

### 方案二：让「取出」永远不扣数（不推荐）

把 RVA 0x3E04F8 与 0x3E072B 的 `FF 4F 28`（`DEC DWORD PTR [RDI+0x28]`）改成 NOP。

任何取出都不减少来源数量，属于「全局白拿」：交易、丢弃都会变成「给了别人自己还有」。而且件数组仍会被压缩、数量却不减，同一格会出现「显示 N 个但只有很少几件」的不一致，带耐久的物品尤其容易出问题。

### 方案三：数据层每帧回填（不推荐）

每帧把仓库里关键物品的数量写回一个下限。游戏的「已占格数」是按 `容量 − Σceil(数量 / 格宽)` 现算的，凭空改数量会让已占格数突然变大，容易把容器撑爆或让界面显示错乱。

### 实现时要注意

- 定位用「模块基址 + RVA」；上面的字节只用来确认没认错位置（0x342BEC 那 5 字节在 v6.0.0 上唯一）。
- 改之前先读原始字节比对，只恢复自己写过的字节；如果这一处已经被别的修改器改过（`E8` 变成 `E9` 之类），先判断再决定动不动手。
- 关掉功能时要能原样恢复，否则仓库会持续「只进不出」。
