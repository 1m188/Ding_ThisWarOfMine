# 无限生命 (UnlimitedLife)

## 功能语义

- 无限生命让角色的生命值不再随时间与状态损耗而下降，是最典型的修改器功能之一。
- 游戏中每个角色的生命是一个浮点数值，会随饥饿、伤病、寒冷等状态持续下降，跌破阈值后触发后果（受伤、濒死直至死亡）。
- 无限生命要实现的效果：这条"持续损耗"消失。有两种语义取向：
    - 冻结式——生命停在开启功能瞬间的当前值，不再下降，外观无任何变化；
    - 满值式——生命始终是一个很大（或最大）的值，开启瞬间回满，视觉上夸张但更直观。
- 边界说明：两者都只针对"规则性持续衰减"。若游戏存在对生命的一次性写入（例如某些事件直接改值），冻结式会让它生效且不回滚，满值式会在下个更新周期把值重新写满。

## 游戏实现

- 生命挂在「HP 组件」上：组件的虚表槽位 0xE0（RVA 0x33D5C0 一带）是它的参数事件派发函数，游戏用不同的"事件号"对这个组件做读值、治疗、受伤、按伤势重算。组件布局：
    - `+0x30`：配置对象，其 `+0x20` 是血量上限；
    - `+0x38`：指向实体内部 `+0x2F0` 处的参数子系统对象，该对象 `+8` 处的编号为 7（表示"可衰减的浮点参数"）；
    - `+0x48`：当前血量（float）；
    - `+0x50`：通知对象（血量归零时用）；`+0x60`：通知对象（血量百分比变化时报给 UI）。
- 事件派发：派发函数读事件号后分头处理——20（0x14）受伤结算、27（0x1b）治疗（血量 = 上限 × 载荷比例）、28（0x1c）按伤势重新推算血量、29（0x1d）读当前值与上限。**规则性掉血只走受伤这一条**，它就在 RVA 0x33E150。
- 受伤结算链（伪代码）：

    ```c
    damage = 载荷里的伤害值;                    // 载荷 +0x00
    if (载荷 +0x24 的"必杀"标记 != 0) {         // 游戏自带的即死通道
        血量 = 0;
        走死亡分支;
    }
    伤害 *= 1 − "Shield" 减伤系数;              // 只有带护甲时才乘
    血量 -= damage;                            // 读 → 减 → 写回
    写回;
    if (血量 <= 0) {
        血量 = 0;                              // 夹零
        通知血量归零;
        实体死亡处理（虚函数 +0x2A8）;
        向攻击者/目击者广播事件 0x54;
    } else {
        上报血量百分比（给 UI）;
    }
    汇合：通知实体"血量变了"（虚函数 0x288），并记一条 HPReducers 记录;
    ```

    对应的机器指令是一条四连链：`movss`（读）→ `subss`（减）→ `movss`（写回）→ `comiss`（比较）。在本样本中它位于 RVA 0x33E321、文件偏移 0x33D721。
- 同一组件里还有三条写血量的旁路：治疗（事件 27，直接写"上限 × 比例"）、按伤势重算（事件 28，用 `Wounded` 与 `WoundedMaxValue` 的比例反推）、死亡分支里的夹零。它们都不是"规则性持续掉血"，风灵月影多年只补丁受伤链仍然有效也印证了这一点。反过来，若哪天游戏改成常驻脚本直接写血量，只处理这条链就不够，得改用钩子式持续写值（见下节）。
- 定位锚点：上面这条"读 → 减 → 写回 → 比较"的 15 字节序列 `F3 0F 10 4F 48 F3 0F 5C CE F3 0F 11 4F 48 0F 2F` 在一个完整游戏文件里只出现一处（RVA 0x33E321），所以定位它不需要记硬编码地址，扫这串字节即可；单独的 `subss xmm1,xmm6` 有十几处，不能用来定位。游戏更新后重跑一次这串字节的唯一性校验即可。

### 官方作弊系统

- 游戏内置一套控制台/Lua 脚本命令注册表，其中包含现成的作弊命令：`IAmCheater`、`HealAll`、`ToggleBulletproof`、`IsBulletproofCheatEnabled` 等，另有 `ChangeDwellerParameter`、`GetCurrentDay`、`GetCurrentHour`、`PauseGameClock` 等大量脚本 API。命令通过统一的注册器（名字字符串 + 处理函数指针）挂进 Lua 环境。
- 防弹模式（Bulletproof）的开关是一个布尔旗标，存放在一个 .data 段静态全局配置对象的固定偏移处（本样本：对象 RVA 0x9236E0、旗标偏移 +0x2C6）。受击伤害函数在开头检查这道门：`旗标开启 && 受击者是"Dweller"（居民）→ 直接返回不结算伤害`。也就是说游戏官方的防弹模式自带敌我判断，只保护玩家阵营。
- 该配置对象由 `lea` 指令直接寻址（非堆指针），地址在编译期固定，跨重启不变；对象内容在运行期初始化，但旗标字节的位置不变。
- 另一个作弊旗标 `IAmCheater` 是 .data 段的独立全局字节（本样本 RVA 0x82410D），toggle 语义，与防弹模式互不相关。

## 可选的功能实现方法

- 启用官方防弹旗标（首选，最简单）：直接把游戏自带防弹模式的布尔字节写成 1。开关各只写一个字节，不修改任何代码，不注入任何内存，敌我判断由游戏自己完成（只保护居民）。关闭时写回 0 即完全还原。前置条件是拿到游戏模块基址后加固定偏移；游戏更新后需重新确认偏移（可用旗标读取函数的字节序列做定位锚点）。语义边界：该旗标在受击伤害函数开头生效，挡的是枪击、近战等直接伤害；饥饿、寒冷等持续衰减是否同受保护需实测确认——若不经过受击函数，则此法挡不住，需配合其他方法。
- 中和衰减指令（冻结式，最简单）：把"减法"那 4 字节换成数值等价的空操作（`subss xmm1,xmm6` → `movss xmm1,xmm1`），生命值从此不再被该路径改读改写。开启 = 写入 4 字节，关闭 = 还原，不需要向游戏进程注入任何新代码。前提是写法位置在文件中唯一（见上节的模板唯一性）。
- 一次性 / 持续写值（满值式）：直接把参数对象里的值字段写成大数（如 9,999,999.0）。"一次性"需要先在运行期定位某个存活角色的参数对象实例；"持续"则借助代码钩子每帧执行（见下一条）。
- 代码钩子 + 功能标志（通用框架）：把衰减链开头的指令改成 `jmp`，跳到自己在游戏进程里分配的可执行内存。钩子内部先复刻被覆盖的原指令（未开功能时行为不变），再读一个全局标志——标志打开则改写生命（写满或清零），关闭则原样放行。一个钩子可以同时承载多个功能（无限生命、一击必杀都只是不同标志的分支），代价是要自己实现整套注入基础设施（两级跳板：近页解决相对跳转的距离限制、远页放真正的代码和标志区）。
- 数据与 Mod 路线（不属于修改器）：游戏自带官方 Mod 工具与可编辑的数据包，可以在数据层面调低消耗速率，得到近似"无限生命"的效果，但没有即时锁定。做修改器时一般不走这条，列出来是为了完整。
- 选型建议：首选官方防弹旗标（一个字节、零注入、自带敌我门）；若实测发现持续衰减不受它保护，再叠加中和指令挡住衰减链；还想要"开功能就回满血"则配合一次性写值；计划用同一入口承载多功能时才考虑钩子 + 标志框架。

## FLiNG 实现

风灵月影体系里此功能对应样本 v6.0.0 Plus 8（2019 年 11 月发布）。它采用"代码钩子 + 功能标志"的持续写值方案，结构如下：

- 在衰减链开头写入 5 字节 `jmp`（相对跳转），目标是离游戏模块基址约 −0x10000000 处的一块 4KB 可读可写可执行内存页。修改器启动（尚未开启功能）时就预留这块页（内容全零：不改游戏代码、不建线程）；远页代码在首次开启相关功能时才创建。
- 这块"近页"里只有一条绝对间接跳（`FF25`，8 字节绝对目标），负责突破相对跳转 ±2GB 的距离限制，跳到真正的"远页"代码。
- 远页代码开头复刻原指令（保证未开功能时与原始行为完全一致），随后检查两个 32 位开关标志（位于代码页内固定偏移，本样本为 +0x200 / +0x204）：
    - 无限生命标志打开：把生命覆写为 9,999,999.0（`mov eax,0x98967F` + `cvtsi2ss`）；
    - 一击必杀标志打开：把生命清零（`xorps xmm1,xmm1`）；
    - 都关闭：走复刻的原指令，与原始代码完全等价。
- 开关切换只写这两个标志（写入内存即可生效）；修改器退出时还原游戏补丁并释放两块内存页，不留残留。若退出后仍发现补丁存在，那是异常残留，警告即可。
- 语义细节：写满发生在减法之前——钩子替换的是"读值"指令，随后原位置的减法照常执行（从 9,999,999 再减去一帧衰减），数值始终接近写满值，表现为"每帧锁满"。这也解释了为什么开启瞬间哪怕只剩一丝血也会立刻回满。
- 与官方作弊系统的关系：风灵月影没有使用游戏自带的防弹旗标，而是自成一套钩子体系。它的钩子只按参数类型（类型编号 7）生效，不区分受击者身份——理论上开启后敌人的生命同样被锁满。官方旗标自带"只保护居民"的判断，在这点上官方路径比风灵月影的更精确。
