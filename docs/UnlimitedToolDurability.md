# 无限工具耐久度 (UnlimitedToolDurability)

## 功能语义

游戏如何扣减工具耐久，以及修改器如何让耐久永不减少。

耐久型工具（刀、斧头、锯子等）每次使用会损失一点耐久，耐久归零后工具损毁消失。耐久以浮点数存储，满值通常为物品定义的最大耐久。

无限耐久让工具的耐久值永不下降。实现上有两类思路：一类是冻结当前值（让递减指令失效）；另一类是每次显示或使用前把耐久刷回满值。前者保留了"当前耐久"的真实性（半钝的刀永远半钝），后者则让所有工具永远崭新。FLiNG 两者都做了。

## 游戏实现

耐久数据的组织比背包更嵌套一层。容器对象（与背包系统共用同一套容器结构）的 `+0x20` 处是物品条目数组（每条目 0x40 字节），条目内：

- `+0x18`：物品定义指针，其 `+0x298` 为该物品的最大耐久（float），物品定义为空时用全局常数 1.0。
- `+0x28`：堆叠数量（如 5 发子弹堆成一叠）。
- `+0x30`：**每件耐久数组**——堆叠的每一件物品有独立耐久条目（每条目 0x20 字节），条目内 `+0x18` 为该件的当前耐久（float），`+0x1c` 为占用标志（byte）。

耐久递减函数（RVA 0x319B20）：输入容器和条目索引，从每件耐久数组中取对应条目，`当前耐久 − 衰减量` 后写回；若结果不大于零，该件从堆叠中移除（计数减一、数组整理、发通知）。这是耐久消耗的唯一写点。

耐久消耗的场景函数（RVA 0x2CC420，唯一调用者）：使用工具的完整流程——定位工具条目、检查当前耐久、扣减、耐久归零时播放物品损毁通知（事件号 6）、读取物品定义 `+0x2a8` 处的损毁音效名、调用虚函数（vtable+0x2b8，疑为破损表现）、从容器移除该物品。函数头部同样有调试模式查询（与背包容量、受击伤害共享同一个全局配置对象的查询函数）。

UI 显示链（RVA 0x4836 附近）：读物品定义的最大耐久，将当前耐久换算为归一化比例（相对全局默认值 1.0）后写入界面显示。

## 可选的实现方法

**中和递减指令（首选，最简单）**：递减函数核心是四字节 `subss xmm0, xmm2`（当前耐久减衰减量）。把它替换为四字节 NOP 即可让耐久永不减少。这是纯指令中和，无需注入、无需远页跳板，关功能时写回原四字节即完全还原。与无限生命的"中和减法"是同一个套路。

**周期性写满耐久**：遍历每件耐久数组把所有 `+0x18` 写回最大耐久。纯数据操作，但需要定位容器对象（堆地址），且堆叠内部的耐久数组结构让遍历逻辑较繁琐。

**钩显示点刷满（FLiNG 方案的一部分）**：在 UI 显示函数里植入桩代码，每次显示前把当前耐久写成最大耐久。视觉效果是耐久条永远满格。

## FLiNG 实现

FLiNG Num3 同时下了两手，各对应上面两个思路：

**其一，中和递减**。把递减函数中的 `subss xmm0, xmm2`（RVA 0x319B41，四字节）直接改写为四字节 NOP——耐久值从此不再减少。这处是简单的内联改写，没有跳板。

**其二，显示刷满钩子**。在 UI 显示函数的耐久换算处（RVA 0x48365F，两条指令 `divss` + `mulss` 共九字节）植入跳板：桩代码先比较物品的最大耐久与常数 0，只要最大耐久大于零，就把条目的当前耐久写回最大耐久，然后原样执行被替换的两条指令返回。效果是每次界面显示耐久时，工具都是满耐久状态。

这个功能属于无状态型：开启时同时落下两处改动，关闭时两处全部还原为原始字节，桩内没有旗标分流（远页 +0x300 处的常数 0 只是阈值，不是开关）。跳板结构与无限生命、无限背包一致：五字节跳转 → 近页 → 绝对跳转 → 远页桩 → 回跳原指令后续。

FLiNG 官方备注"一次性工具如开锁器无效"暗示了游戏内存在两类消耗品：可重复使用的耐久型工具（刀、斧、撬棍等）和一次性消耗品（开锁器、绷带等），后者用完即消失，没有耐久概念。

综合效果：递减被中和保证耐久数值不降；显示钩子保证界面永远显示满格。双重保障下即便某处漏了（例如存档重载后耐久被重算），显示层也会把它刷回满值。一次性工具（开锁器等）没有耐久数组，走的是"使用即移除"路径，两处改动都管不到——这就是 FLiNG 备注"一次性工具无效"的技术根源。
