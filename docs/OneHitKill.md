# 一击必杀 (OneHitKill)

## 功能语义

游戏里每个角色（以及所有有生命值的实体）都有一个浮点数的当前血量。受到攻击时，游戏从"当前血量"里减去这次伤害，减完看结果：还大于 0 就继续活着，小于等于 0 就进入死亡流程。

"一击必杀"指的是：不管这次伤害的数值有多小、有没有被护甲削掉，只要命中就当场死亡。

几个必须说清楚的边界：

- 它改的是"扣血"这一步，不改命中判定。打不中依然不致命。
- 这段扣血代码是所有带生命值的实体共用的，玩家角色也走同一条。改这里就会连玩家一起改，这一点和风灵月影的做法一致（它把"一击必杀"和"无限生命"放在同一个钩子上，两个开关只是翻旗标，见后文）。
- 游戏自己还有一条"必杀通道"：伤害数据里有一个字节，非 0 时直接跳过扣血计算、把血设成 0 再走死亡流程（见下）。官方作弊开关（配置对象 `0x9236E0` 的 `+0x2C6` 字节，取值函数 RVA `0x140213920`）会让"居民"（标签 `Dweller`）彻底免疫这条路径。这些是游戏自带机制，不是本功能，但可以复用。

## 游戏实现

### 组件身份

血量属于 `KosovoHPComponent` 组件（MSVC RTTI 类名 `.?AVKosovoHPComponent@@`）。它的虚表在 RVA `0x6539D8`（前一个 8 字节 `0x6539D0` 是指向 RTTI 定位符的指针，不算槽位），第 28 号槽位（偏移 `0xE0`）是参数事件处理函数，RVA `0x33D5C0`。

Ghidra 对受伤函数的分析结果（`FUN_14033e150(longlong param_1, float *param_2)`）里，`callers` 只有 `FUN_14033d5c0` 这一个，说明受伤处理是从事件派发器直接调进来的。

字段含义（`this` = 组件对象）：

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| `+0x30` | 指针 | 配置对象，`+0x20` 是血量上限 |
| `+0x38` | 指针 | 指向实体的组件块，实体本体 = 该指针 − `0x2F0` |
| `+0x48` | float | 当前血量 |
| `+0x50` | 指针 | 血量归零时要通知的对象 |
| `+0x60` | 指针 | 血量变化（按百分比）时要通知的对象 |

伤害数据（`param_2`，也叫事件载荷）的字段：

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| `+0x00` | float | 这次伤害的数值 |
| `+0x08` | 指针 | 攻击者（带引用计数） |
| `+0x10` | byte | 标志位，非 0 时广播事件 200 |
| `+0x14` | int | 命中类型 |
| `+0x20` | int | 命中部位/角度相关 |
| `+0x24` | byte | **必杀标记**，非 0 直接致死 |
| `+0x25` | byte | 处理结果（被致死流程置 1） |
| `+0x26` | byte | 跳过标记 |
| `+0x31` | byte | 命中标志 |
| `+0x34` | float | 传给死亡处理的参数 |

### 事件派发

`0x33D5C0` 收三个参数：组件对象、事件类型（`r8d`）、载荷指针（`r9`）。事件类型大于 0x1D 直接走默认处理；否则用一张 7 项的跳转表（RVA `0x33D7E0`）加一张 30 字节的映射表（RVA `0x33D7FC`）分派：

| 事件类型 | 处理函数 | 做什么 |
| --- | --- | --- |
| 0 | `0x33D62A` → `0x14033F4C0` | 另一类参数事件 |
| 9 | `0x33D637` | 血量推成 0 的通知 |
| 20 (0x14) | `0x33D61A` → `0x14033E150` | **受到伤害** |
| 27 (0x1b) | `0x33D657` | 治疗：血 = 上限 × 载荷里的比例 |
| 28 (0x1c) | `0x33D673` | 按受伤程度反算血量（见后） |
| 29 (0x1d) | `0x33D797` | 读取当前血与上限，写回载荷 |

### 受伤流程（RVA `0x33E150`）

Ghidra 反编译出的主干（去掉与配装、日志相关的部分）：

```c
void FUN_14033e150(longlong this, float *dmg)
{
  entity = *(longlong *)(this + 0x38) - 0x2f0;      // 组件块 → 实体本体
  if (game->cheat_bulletproof != 0 &&               // 官方作弊开关
      IsTag(entity, "Dweller"))                     // 只保护居民
    return;                                         // 直接免伤

  dmg->processed = 0;
  if (dmg->value > 0.0 && dmg->skip == 0) { /* 配装/表现层处理，与本功能无关 */ }

  if (dmg->instant_kill == 0) {                     // ← 必杀标记为 0，走正常扣血
    f = dmg->value;
    if (f > 0.0)
      f = f * (1.0 - ShieldFactor(entity, "Shield"));   // 护甲减伤
    f = *(float *)(this + 0x48) - f;                // 当前血 − 伤害
    *(float *)(this + 0x48) = f;
    if (f > 0.0) {                                  // 还活着
      if (*(longlong *)(this + 0x60) != 0)
        NotifyPercent(*(longlong *)(this + 0x60), f / max_hp);  // 血量百分比
      goto after;
    }
  } else {
    *(float *)(this + 0x48) = 0;                    // 必杀标记 → 血直接归零
  }

death:                                              // 死亡分支
  *(float *)(this + 0x48) = 0;
  if (*(longlong *)(this + 0x50) != 0)
    NotifyZero(*(longlong *)(this + 0x50), 0, 1);
  (*(entity->vtbl + 0x2A8))(entity, &type7, *(float *)(dmg + 0x34),
                            *(int *)(dmg + 0x14), *(byte *)(dmg + 0x31));   // 死亡处理
  if (dmg->attacker != 0 && *dmg->attacker != 0) {  // 有攻击者
    BuildEvent(local);
    Broadcast(*(longlong *)(this + 0x38) + 0x2F0, 0x54, local, 1);   // 广播"被打死"事件
    if ((*(byte *)(*dmg->attacker + 0x34) & 2) != 0)
      BroadcastWitness(&DAT_140925910, *dmg->attacker, local, 4);     // 目击者
    FreeEvent(local);
  }
  dmg->processed = 1;

after:
  (*(entity->vtbl + 0x288))(entity, *(float *)(this + 0x48), max_hp);  // 血量变化通知
  LogToHPReducers(this + 0x1FC8, dmg);              // 把这次伤害记进 HPReducers 列表
  if (dmg->hit_type == 1) { /* 受伤进度相关，未展开 */ }
}
```

对应的关键指令位置（RVA）：

| RVA | 指令 | 说明 |
| --- | --- | --- |
| `0x33E2C3` | `44 38 66 24` `cmp [rsi+0x24], r12b` | 判必杀标记（`r12d` 在函数入口 `0x33E1A3` 被清零，等价于跟 0 比） |
| `0x33E2C7` | `74 06` `je 0x33E2CF` | 标记为 0 → 走正常扣血 |
| `0x33E2C9` | `44 89 67 48` `mov [rdi+0x48], r12d` | 标记非 0 → 血直接写 0 |
| `0x33E2CD` | `EB 69` `jmp 0x33E338` | 跳到死亡分支 |
| `0x33E2CF` | `F3 0F 10 36` `movss xmm6,[rsi]` | 取伤害值 |
| `0x33E321` | `F3 0F 10 4F 48` `movss xmm1,[rdi+0x48]` | 取当前血（风灵月影的钩子点） |
| `0x33E326` | `F3 0F 5C CE` `subss xmm1,xmm6` | 当前血 − 伤害 |
| `0x33E32A` | `F3 0F 11 4F 48` `movss [rdi+0x48],xmm1` | 写回 |
| `0x33E32F` | `0F 2F CF` `comiss xmm1,xmm7` | 和 0 比较 |
| `0x33E332` | `0F 87 AD 00 00 00` `ja 0x33E3E5` | 还大于 0 → 存活分支 |
| `0x33E338` | 死亡分支入口 | 血归零 + 死亡处理 |

### 另一条改血的路（事件 28）

`0x33D673` 不是攻击路径，而是"按受伤程度反算血量"的同步：先按实体类型过滤（`0x1400BD7D0` / `0x1400BDAD0` 传类型码 `0x303`），再用字符串 `WoundedMaxValue`（RVA `0x637950`）和 `Wounded`（RVA `0x5E8370`）取到两个值，算 `1 − Wounded/WoundedMaxValue` 夹到 `[0,1]`，乘以血量上限写回。风灵月影的钩子不覆盖这一条。

### 谁发出伤害事件

这一项没有解开，如实记录：

- 受伤函数在全文只有一个直接调用点（`0x33D620`，就在派发器里）。
- 派发器本身只有虚表引用，没有直接调用者。
- 全文 27 处 `call [reg+0xE8]` 逐一检查过，都不是这个派发器（它们属于别的组件的同名槽位）。
- 搜索事件号 20 的立即数（`mov r8d,0x14` 等）也没有可靠命中。

结论：伤害事件由引擎的事件/虚表机制派发，静态上没能定位"哪一行代码发起攻击、把事件送进来"。这不影响本功能的实现——补丁点是受伤函数内部，与谁触发无关。

## 可选的功能实现方法

定位统一用「模块基址 + RVA」：RVA 每次启动不变，只有模块基址随地址随机化变。字节特征只用来确认"这处没认错"，不用来搜索定位。

### 方案一：把"必杀标记是否为 0"的判断抹掉（推荐）

```text
位置：RVA 0x33E2C7，2 个字节
原始：74 06            je 0x33E2CF
补丁：90 90            nop ×2
```

判断被抹掉后，每次受伤都直接落到"血写 0 + 跳死亡分支"，等价于"任何伤害即死"。

- 优点：只改 2 个字节，不申请代码页、不注入、不留标志，和本项目其他功能同一套路。
- 上下文锚点 `44 38 66 24 74 06` 全文只有 1 处，可以用来确认位置。
- 代价：对所有实体生效，包括玩家自己。想只杀敌人用方案三。

### 方案二：把"当前血"当 0 来减（风灵月影同款切入点的简化版）

```text
位置：RVA 0x33E326，4 个字节
原始：F3 0F 5C CE      subss xmm1, xmm6
补丁：0F 57 C9 90      xorps xmm1, xmm1 ; nop
```

原本是"当前血 − 伤害"，改成"0 再减伤害"，结果必然小于等于 0，直接进死亡分支。

- 和方案一只差"从哪一句切入"，副作用一样（对玩家也生效）。
- 注意 `F3 0F 5C CE` 全文有 17 处，不能拿来当搜索特征；要连前后一起看，`F3 0F 10 4F 48 F3 0F 5C CE F3 0F 11 4F 48 0F 2F` 这 15 个字节才唯一（全文 1 处）。

### 方案三：只杀敌人（挂钩，风灵月影结构 + 一句标签判断）

风灵月影的 stub 已经证明"在 `0x33E321` 挂钩、把读到的当前血换成别的值"是可行的。把它的两个全局标志换成"目标是不是居民"就行：

```text
挂钩点：RVA 0x33E321，5 个字节
原始：F3 0F 10 4F 48      movss xmm1, [rdi+0x48]
补丁：E9 xx xx xx xx      jmp 自己的代码页

代码页里的 stub：
    movss xmm1, [rdi+0x48]          ; 照抄原指令
    mov   rax, [rdi+0x38]           ; 组件块
    test  rax, rax
    jz    .back
    lea   rcx, [rax-0x2f0]          ; 实体本体
    lea   rdx, ["Dweller"]          ; RVA 0x5E62F0 的字符串
    call  0x140254D60               ; 游戏自带的标签判断
    test  al, al
    jnz   .back                     ; 是居民 → 原样返回，正常扣血
    xorps xmm1, xmm1                ; 不是居民 → 当前血当 0
.back:
    jmp   base+0x33E326             ; 回到 subss 那一句
```

- 复用的是官方"无敌开关"用的同一个标签判断函数（`0x140254D60`），语义一致：居民受到保护，其他实体一击必死。
- 这个方案要申请可执行内存页，和本项目"就地改字节、不注入"的取向不同，只有在方案一实测出"玩家也死"确实不可接受时才做。

### 实现时要注意

- 关闭时先把当前内存读出来比对：等于原始字节说明本来没开；等于补丁字节说明是自己开的，写回原始字节；其余情况按冲突处理，不要覆盖（风灵月影也可能开着）。
- 只恢复自己写过的字节。
- 方案一的补丁落在"必杀标记"判断上，顺带把"伤害 ≤ 0 就跳过"之类的分支也绕过了：任何送达这个函数的事件都会致死。这是设计意图，不是 bug。
- 所有 RVA 都基于当前这份 v6.0.0（2019 年）可执行文件的布局。

## FLiNG 实现

版本：This War of Mine v6.0.0 Plus 8 Trainer（2019-11-18）。手法是挂钩（hook），不是就地改一个分支。

补丁点与跳转链：

| 位置 | 内容 |
| --- | --- |
| RVA `0x33E321`（游戏 `.text`） | `F3 0F 10 4F 48` → `E9 DA 1C CC EF`（5 字节相对跳转，跳到它自己申请的私有页） |
| 私有页（近页） | `FF 25 …` 间接跳转，指向远页代码 |
| 远页 | 真正的替换逻辑（下面这段） |

远页 stub 的字节与含义（从运行时内存读出，一字节不差）：

```text
0x00  F3 0F 10 4F 48         movss xmm1,[rdi+0x48]     ; 照抄原指令：先读当前血
0x05  50                     push rax
0x06  48 8B 47 38            mov  rax,[rdi+0x38]       ; 组件块
0x0A  48 85 C0               test rax,rax
0x0D  74 26                  je   0x35                 ; 没有描述符 → 直接返回原值
0x0F  83 78 08 07            cmp  dword [rax+8],7      ; 参数类型号 == 7
0x13  75 14                  jne  0x29                 ; 类型≠7 → 走旗标 B 那一支
0x15  83 3D E4 01 00 00 01   cmp  dword [rip+0x1E4],1  ; 旗标 A（远页 +0x200）= 无限生命
0x1C  75 17                  jne  0x35                 ; A 不为 1 → 返回原值
0x1E  B8 7F 96 98 00         mov  eax,0x98967F         ; 9,999,999
0x23  F3 0F 2A C8            cvtsi2ss xmm1,eax         ; 当前血 = 9,999,999.0f
0x27  EB 0C                  jmp  0x35
0x29  83 3D D4 01 00 00 01   cmp  dword [rip+0x1D4],1  ; 旗标 B（远页 +0x204）= 一击必杀
0x30  75 03                  jne  0x35                 ; B 不为 1 → 返回原值
0x32  0F 57 C9               xorps xmm1,xmm1           ; 当前血当 0
0x35  58                     pop  rax
0x36  FF 25 00 00 00 00      jmp  [rip+0]              ; 跳回游戏 RVA 0x33E326（subss 那一句）
```

结构和语义：

- 它把"当前血量"这个输入替换掉，再让游戏自己的 `subss` 去减。旗标 B 那一路把血量换成 0，减完必然小于等于 0，于是走游戏自己的死亡分支——这就是"一击必杀"的全部机制。
- 走哪一支由"参数描述符 +8 处的类型号是不是 7"决定：等于 7 看旗标 A，不等于 7 看旗标 B。两个旗标都在钩子自己申请的远页里，地址 `+0x200` / `+0x204`，都是 dword，值为 1 才生效。
- 钩子在第一次按下开关、功能真正生效时装好并常驻；之后开关只翻旗标，不再动代码段。关闭功能也不是"卸载钩子"，而是把旗标写回 0。

实测核对（本轮做的，只读内存 + 后台按键，没有碰用户前台）：

| 操作 | 远页 `+0x200` | 远页 `+0x204` | `.text` 补丁点 |
| --- | --- | --- | --- |
| 初始（什么都没开） | 0 | 0 | 原始 `F3 0F 10 4F 48` |
| 按一次小键盘 1（无限生命） | **1** | 0 | `E9 DA 1C CC EF`（钩子装上） |
| 再按一次小键盘 1 | 0 | 0 | 钩子仍在（只翻旗标） |
| 按一次小键盘 0（一击必杀） | 0 | **1** | 代码段**一个字节都没变** |
| 再按一次小键盘 0 | 0 | 0 | 代码段零变化 |

由此可以确定：`+0x200` 是无限生命、`+0x204` 是一击必杀，两者共用一个钩子，切换功能只改旗标。

几点值得对比：

- 它没有改 `0x33E321` 之后的任何一句，也没有动"必杀标记"分支；语义完全落在"把读到的当前血换成常量"上。方案二（`xorps` 覆盖 `subss`）得到的是同一个效果，只是把替换写在游戏代码里而不是 stub 里。
- 两支都不判断对象身份（没有 `Dweller` 之类的判断），所以一旦进入某支，对被击中的对象一视同仁；要做"只杀敌人"必须自己加判断（见方案三）。
- 一份遗留的不确定：类型号 7 具体代表哪种参数、角色血量参数登记的又是哪个类型号，本篇没有在运行时读组件描述符坐实。按字节只能确定"类型号是不是 7 决定走哪一支"，不能替它推断"哪个开关对玩家血量真正有效"。这一条留给以后实测（比如开一击必杀后真打一次看是否一击致死）更合适，不在这里下结论。
- `.text` 那 5 个补丁字节每次启动都一样（`E9 DA 1C CC EF`）：跳转目标固定在「模块基址 − 0x10000000」，相对偏移是个常数，所以不随地址随机化变化。
- 补丁字节的来源：修改器文件里搜不到这些原指令字节，也搜不到这些 RVA（它把补丁数据编码后存着，运行时才解出来），所以上面这张表是从运行时内存差异读出来的（按一次热键比对整段代码段，只有这几个字节变化；再按一次精确还原）。

关于修改器本身的静态证据（REA/Ghidra 概览 + 导入表）：
- 镜像为 x64 PE，基址 `0x140000000`，8 个段，Ghidra 识别出 2711 个函数、1032 个字符串。
- 导入表只有 96 项，全是 `KERNEL32.dll` 一类的基础函数，**没有任何进程内存 API**（没有 `OpenProcess`、`ReadProcessMemory`、`WriteProcessMemory`、`VirtualAllocEx`、`VirtualProtectEx`）；它靠导入表里的 `LoadLibraryW` / `GetProcAddress` 在运行时按名字解析这些函数。
- 它的字符串表里能看到 `VirtualQuery`、`VirtualAlloc`、`VirtualProtect`、`GetThreadContext`、`SetThreadContext`、`SuspendThread`、`ResumeThread`、`FlushInstructionCache`、`CreateToolhelp32Snapshot` 这一组名字（线程注入/内存操作工具箱），但没有 `WriteProcessMemory` 之类的明文名字——和"补丁数据运行时才解出来"是同一个现象。
- 所以从修改器文件静态反推它的补丁点做不到；本节的补丁表必须靠运行时验证，这一点和"功能语义"无关，是修改器自身的保护手段决定的。
